Home page — fetching profile

1. home.html (the page)

html
<h2>Welcome, {{ user.name }}</h2>
<p>Email: {{ user.email }}</p>
<p><strong>Mobile: {{ user.mobile }}</strong></p>

Displays user.name, user.email, user.mobile — but user starts as undefined (declared as user: any; with no initial value). This template binding works because Angular just renders nothing until user gets populated.

2. Home.ts → ngOnInit()

typescript
ngOnInit() {
  this.authService.getUserProfile().subscribe({
    next: (data) => {
      console.log(data);
      if (data.status == 'success') {
        this.user = data.data;
        this.cdr.detectChanges();
      }
    },
    error: (err) => console.log(err)
  });
}

ngOnInit() runs automatically the moment the Home component loads (right after router.navigate(['/home']) swaps it in). It immediately calls the service → jumps to →

3. auth-service.ts

typescript
getUserProfile(): Observable<any> {
  return this.http.get(`${this.baseUrl}/user`, { withCredentials: true });
}

GET http://localhost:5000/api/user, withCredentials: true → browser auto-attaches the token cookie stored during login → jumps to →

4. app.js

javascript
app.get("/api/user", async (req, res) => {
  const token = req.cookies.token;
  const decoded = jwt.verify(token, JWT_SECRET);
  const user = await User.findById(decoded.id).select('-password');
  return res.status(200).json({ status: 'success', data: user });
});

Verifies the cookie's JWT, fetches the user from MongoDB (minus password) → responds.

5. Back to Home.ts

typescript
this.user = data.data;
this.cdr.detectChanges();

data.data is the user object from step 4's response → assigned to this.user → template (home.html) immediately re-renders with real name/email/mobile.

Why this.cdr.detectChanges() is here: normally Angular auto-detects changes and updates the view. This manual call forces an immediate re-render — likely added because the response arrives via an async HTTP callback and the developer wanted to guarantee the UI updates right away rather than waiting for Angular's next automatic change-detection cycle.

Logout — from the Home page

1. home.html

html
<button (click)="logout()" class="btn-primary">Logout</button>

User clicks → (click) fires logout() in Home.ts → jumps to →

2. Home.ts

typescript
logout() {
  this.authService.logout().subscribe({
    next: (data) => {
      window.alert(data.message);
      this.router.navigate(['/login']);
    },
    error: (err) => {
      console.log(err);
      window.alert('Error logging out. Please try again.');
    }
  });
}

Calls the service → jumps to →

3. auth-service.ts

typescript
logout(): Observable<any> {
  return this.http.post(`${this.baseUrl}/logout`, {}, {withCredentials: true});
}

POST http://localhost:5000/api/logout → jumps to →

4. app.js

javascript
app.post("/api/logout", (req, res) => {
  res.clearCookie('token', { httpOnly: true, secure: false, sameSite: 'strict' });
  return res.status(200).json({ status: 'success', message: 'Logout successful' });
});

Sends a Set-Cookie that expires the cookie immediately — browser deletes token from its jar.

5. Back to Home.ts

typescript
window.alert(data.message);        // shows "Logout successful" popup
this.router.navigate(['/login']);  // page changes: Home → Login

Matches {path:"login", component:Login} in your route table → renders Login component.
